Прокси для SEO: когда нужен IP города, а когда хватит API поисковика

Автор — Сергей · опубликовано 23 ноября 2026

Коротко

Прокси для SEO нужны, чтобы увидеть свой сайт и поиск глазами посетителя из конкретного города: выдача Яндекса и Google зависит от местоположения, а его определяют в том числе по IP. Для регулярного съёма позиций в Яндексе есть официальный Yandex Search API с выбором региона, для своих сайтов есть Вебмастер и Search Console. Прокси с выбором города остаются для проверок, которые эти инструменты не закрывают.

Почему позиции сайта отличаются в разных городах

Позиции различаются, потому что поисковики подстраивают ответ под регион пользователя. Один и тот же запрос в Москве и в Казани может дать разный список сайтов, если он геозависимый.

В архивном материале Яндекса о поиске с учётом региона сказано, что таких запросов от 15 до 30%, в зависимости от региона. Там же написано, что регион пользователя определяется прежде всего по IP-адресу, а если город указан в самом запросе, приоритет получают сайты этого города. Материал помечен как архивный, поэтому цифру стоит считать ориентиром, а не свежим замером.

У сайта тоже есть регион. В справке Яндекс Вебмастера о регионе сайта указано, что региональность учитывается при показе результатов по геозависимым запросам и не исключает сайт из выдачи в других регионах. Регион задают или меняют в Вебмастере, а модератор сверяет его с содержимым сайта.

Google определяет местоположение по нескольким источникам. В справке Google о местоположении в Поиске IP-адрес назван одним из них, наряду с точным местоположением устройства, если пользователь дал к нему доступ.

Какие задачи SEO решают прокси, а какие закрывают официальные инструменты

Прокси нужны там, где важен именно адрес в городе: посмотреть свой сайт и его региональные версии так, как их видит посетитель оттуда. Сами позиции по регионам удобнее брать из официальных каналов поисковиков.

В таблице собраны типовые задачи SEO-команды и инструмент, с которого разумно начать. Сведения о возможностях инструментов взяты из их документации, ссылки даны в разделах ниже.

Что поисковики пишут об автоматических запросах

Оба поисковика ограничивают автоматические запросы к выдаче вне официальных каналов. Это первое, что стоит прочитать до того, как строить свой сборщик позиций на прокси.

В лицензии на использование поисковой системы Яндекса в п. 6.6 сказано, что пользователь не вправе делать автоматические запросы к сервису иначе как с соблюдением требований условий Yandex Search API. Версия лицензии опубликована 17 сентября 2026.

В правилах Google Search Central машинный трафик описан как отправка автоматизированных запросов в Google. Туда же Google относит сбор результатов для проверки позиций и любой автоматизированный доступ к Поиску без явного разрешения.

Отсюда рабочее правило. Позиции в Яндексе снимайте через Search API, данные своих сайтов берите из Вебмастера и Search Console. Если сервис съёма позиций, которым пользуется команда, просит ваши собственные прокси, прочитайте его условия вместе с условиями поисковика и уточните схему у юриста компании.

Как снимать позиции в Яндексе через Search API

Yandex Search API отдаёт выдачу Яндекса по запросу из кода, и регион в нём задаётся параметром, а не IP-адресом. Поэтому для съёма позиций в Яндексе прокси не нужны.

В описании Yandex Search API сказано, что сервис можно использовать в том числе для отслеживания позиций сайтов в выдаче Яндекса. Текстовый поиск работает в синхронном и отложенном режиме, результаты приходят в XML или HTML.

Регион задают полем lr. На странице регионов поиска в таблице частых регионов у Москвы указан ID 213, у Санкт-Петербурга ID 2, у России в целом ID 225. Полный список регионов получают методом Wordstat.getRegionsTree.

Квоты, которые определяют темп съёма

Объём съёма ограничивают квоты, и их стоит посчитать до старта. На странице квот и лимитов Yandex Search API указано:

  • синхронных запросов: 1 в секунду и 10 000 в час;
  • отложенных запросов: 1 в секунду и 35 000 в час;
  • отложенные запросы доступны только с 00:00 до 06:00 по московскому времени;
  • на один запрос возвращается не более 250 результатов.

Квоты организационные, их можно увеличить через техподдержку. Лимит в 250 результатов технический и не меняется.

Условный пример расчёта

Условный пример: команда отслеживает 500 запросов в 10 городах раз в сутки. Это 500 × 10 = 5 000 запросов к API за один съём.

При квоте 1 запрос в секунду 5 000 запросов уйдут за 5 000 секунд, это 1 час 23 минуты. Ночное окно отложенного режима длится 6 часов, то есть 21 600 секунд, и такой съём в него помещается с запасом.

Если запросов 3 000 в тех же 10 городах, получится 30 000 запросов и 30 000 секунд. Это больше ночного окна, и тогда нужно либо делить съём на две ночи, либо просить увеличить квоту.

Позиции своего сайта в Вебмастере и Search Console

Для своих сайтов позиции и показы по регионам уже есть в панелях поисковиков. Прокси для этой задачи не нужны, но у каждой панели есть границы.

В справке Вебмастера о статистике поисковых запросов сказано, что статистику можно смотреть с учётом региона, в котором вы продвигаете сайт, и типа устройства. Позиция в отчёте показывается средним значением за весь день. Регионы попадают в список, если у сайта был хотя бы один показ на первых 50 позициях.

В справке Search Console об отчёте об эффективности средняя позиция определена как среднее положение самого верхнего результата, относящегося к вашему сайту. Разрезы отчёта: запросы, страницы, страны, устройства, вид в поиске и даты. Городов среди них нет, поэтому позиции Google по городам эта панель не покажет.

Обе панели показывают только ваш сайт. Позиции конкурентов и полный список сайтов по запросу в них не видны.

Какой тип прокси выбрать для региональных проверок

Для проверок по городам главное условие одно: сервис должен давать выбор города, а не только страны. Тип адреса выбирают по сайту, который вы проверяете.

Серверные IPv4 подходят для проверок своих сайтов. Адрес закреплён за вами на срок аренды, его легко добавить в список разрешённых на своём сервере, а в логах сразу видно, какой город проверялся.

Ротационные серверные нужны, когда проверок много и их удобнее раздавать по пулу адресов. Для пошаговой проверки, например выбора города на сайте и перехода в каталог, нужна sticky-сессия (один IP на время сессии). Подробнее о режимах ротации написано в статье о прокси для парсинга.

IPv6-адреса подходят, только если ваш сайт отвечает по IPv6. Проверьте у домена DNS-запись AAAA: по RFC 3596 запись этого типа хранит один IPv6-адрес. Нет записи AAAA, значит, у имени сайта нет IPv6-адреса, и проверка с IPv6-прокси до него не дойдёт.

Сколько адресов нужно

Число адресов считают от числа городов и параллельных проверок. Условный пример: команда проверяет региональные версии сайта в 10 городах, по 2 параллельных потока на город. Нужно 10 × 2 = 20 адресов, по 2 в каждом городе.

Если город меняется редко, а проверки идут по очереди, хватит одного адреса на город. Если сервис продаёт адреса только на страну без выбора города, для этой задачи он не подходит.

Как проверить, что поисковик видит нужный город

Перед работой проверьте, какой регион поисковик приписал адресу: город в описании тарифа и город, который определил поисковик, могут не совпасть.

В справке Google об IP-адресах сказано, что IP-адреса лишь в определённой степени зависят от географии, а иногда Google не может определить местоположение по IP вообще. В справке о местоположении в Поиске добавлено, что сведения о нём показываются внизу страницы с результатами, и если использовался IP, там стоит пометка «Определено по IP-адресу».

В справке Яндекса о выборе города сказано, что по умолчанию город определяется по IP-адресу устройства, а его название видно на главной странице Яндекса под строкой поиска.

Для каждого купленного адреса запишите три вещи:

  • какой город указан у адреса в личном кабинете сервиса;
  • какой город Яндекс показывает под строкой поиска и что написано внизу выдачи Google;
  • открывается ли региональная версия вашего сайта с тем же городом.

Если город не совпал, напишите в поддержку сервиса до того, как строить на этом адресе регулярные проверки. Как устроить пробную закупку и что сверить в условиях до оплаты, разобрано в статье о выборе прокси для компании.

Вопросы и ответы

Нужны ли прокси для сбора позиций в Яндексе?
Для регулярного съёма позиций в Яндексе есть официальный Yandex Search API. Регион в нём задаётся полем lr, например 213 для Москвы, поэтому адрес в городе не нужен. Лицензия поисковой системы Яндекса разрешает автоматические запросы только с соблюдением условий этого API.
Как проверить позиции сайта по городам без прокси?
Для своего сайта откройте статистику поисковых запросов в Яндекс Вебмастере и выберите регион продвижения: там видна средняя позиция за день. В Google Search Console позиции делятся по странам, городов в отчёте нет. Позиции конкурентов в этих панелях не показываются.
Какие прокси подходят для SEO-проверок по регионам?
Главное условие — выбор города, а не только страны. Для проверок своих сайтов подходят серверные IPv4, ротационные нужны при большом числе проверок. IPv6-адреса подходят, только если у домена есть DNS-запись AAAA.
Сколько прокси нужно для проверки сайта в разных городах?
Число адресов считают как число городов, умноженное на число параллельных проверок в каждом городе. Для 10 городов и двух потоков на город нужно 20 адресов. Если проверки идут по очереди, хватит одного адреса на город.
Почему Google показывает не тот город, что указан у прокси?
Google определяет местоположение по нескольким источникам, и IP-адрес только один из них. По справке Google, IP лишь в определённой степени связан с географией, а иногда местоположение по нему не определяется. Внизу страницы результатов видно, определён ли город по IP-адресу.
