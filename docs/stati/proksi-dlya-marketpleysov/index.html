Прокси для маркетплейсов: как следить за ценами и наличием по регионам

Автор — Сергей · опубликовано 20 ноября 2026

Прокси для маркетплейсов нужны, чтобы видеть открытые карточки конкурентов, их цены, наличие и поисковую выдачу так, как их видит покупатель в конкретном городе. Свои цены, остатки и продажи по регионам берите из API площадки и отчётов кабинета, а прокси выбирайте по городу, режиму сессии и модели оплаты.

Какие задачи на маркетплейсах закрывают прокси

Прокси закрывают только ту часть мониторинга, где данные лежат на открытых страницах площадки: карточки чужих товаров, выдача по запросу, наличие в регионе. Всё, что касается вашего магазина, удобнее и точнее получать из инструментов для продавцов.

В таблице разложены типовые задачи аналитика и продавца: откуда брать данные и что для этого нужно. Тип прокси в правой колонке означает стартовую точку для теста, а не окончательный выбор.

Задача Откуда данные Что нужно
Свои цены, скидки, остатки API площадки токен продавца, прокси не нужны
Свои продажи по регионам отчёты кабинета продавца доступ к кабинету
Цены конкурентов в одном городе открытые карточки серверные IPv4 или резидентские
Цены и наличие в нескольких городах открытые карточки и выдача резидентские с выбором города
Позиции товара в поиске по регионам поисковая выдача площадки выбор города, sticky-сессии
Ежедневная проверка большого каталога открытые карточки ротационные серверные или резидентские

Сравнение сервисов с домашними адресами собрано в рейтинге резидентских прокси. Если для вашей задачи хватает адресов дата-центров, смотрите рейтинг серверных прокси IPv4.

Свои данные берите из API площадки, а не со страниц

Для собственного магазина API площадки даёт структурированные данные без прокси и без разбора страниц. Прокси для этой части мониторинга не нужны, а данные из кабинета точнее того, что видно на витрине.

В справке Wildberries статья «Что такое WB API» описывает его как программный интерфейс для обмена информацией с магазином продавца. Через него подключают сторонние сервисы и собственные программы, например учётную систему 1С.

Какие данные доступны, определяет токен. В статье Wildberries о категориях данных WB API сказано, что их 13 и каждая открывает доступ к определённой информации вашего магазина. Для мониторинга полезны три:

  • «Цены и скидки»: управление ценами своих товаров и участие в акциях;
  • «Аналитика»: воронка продаж, поисковые запросы покупателей, отчёты по остаткам на складах;
  • «Маркетплейс»: заказы и обновление остатков на складах продавца.

Там же указано, что для аналитики безопаснее выбирать уровень доступа «только чтение». В справке о подключении по токену сказано, что срок действия токена 180 дней. Потом его нужно перевыпустить, иначе интеграция потеряет доступ к данным.

Описание категории «Цены и скидки» прямо называет сценарий, когда продавец меняет свои цены в зависимости от цен конкурентов. Сами цены конкурентов эти категории не отдают: они описывают данные вашего магазина. Чужие карточки остаются открытыми страницами, и для них нужны прокси.

Почему цены и наличие зависят от города

Срок доставки, наличие товара на складе рядом с покупателем и место в выдаче связаны с регионом, и Wildberries прямо пишет об этом в справке для продавцов. Поэтому мониторинг из одного города не показывает, что видит покупатель в другом.

Связь доставки и выдачи Wildberries описывает в справке об отчёте «География заказов». Отчёт показывает среднее время от заказа до пункта выдачи по регионам. В той же справке сказано, что чем ниже среднее время, тем выше позиции товаров в поиске.

Для конкурентного анализа отсюда два вывода:

  • среднее время доставки считается по регионам, поэтому позиции одного товара по одному запросу в разных регионах могут отличаться;
  • наличие и срок доставки у конкурента зависят от того, на каких складах лежит его товар.

Как площадка определяет регион посетителя, проверьте на тесте до закупки. Проверьте три варианта: адрес доставки, выбранный на сайте, cookie и адрес подключения. От этого зависит, нужен ли вам прокси в каждом городе или достаточно сохранять выбранный адрес в сессии.

Резидентские или серверные адреса для мониторинга цен

Для мониторинга цен в одном городе сравнение можно начать с серверных IPv4, а для нескольких городов и выдачи как у покупателей смотрят резидентские адреса с выбором города. Окончательный ответ даёт тест на самой площадке.

Серверные IPv4 выдают дата-центры, и на время аренды адрес остаётся вашим. Ошибку по такому адресу легко найти в логах скрипта. У ротационных серверных адрес берётся из общего пула и меняется сам, по таймеру или с каждым новым запросом.

Резидентские адреса относятся к домашним подключениям. Их выбирают в двух случаях:

  • нужен адрес в конкретном городе, а не просто в стране;
  • на тесте видно, что адресам дата-центров площадка показывает страницы иначе, чем обычным покупателям.

Выбор города в рейтинге засчитан как отдельное условие. Он бывает у разных типов прокси, поэтому на карточке сервиса смотрите, к какому типу относится выбор города.

Ротация, sticky-сессии и выбор региона

Для проверки каталога по отдельным карточкам подходит ротация, а для цепочки «выбрать город, открыть выдачу, пролистать страницы» нужна sticky-сессия (один IP на время сессии). Иначе выбранный регион и cookie сбрасываются посреди проверки.

Независимые запросы встречаются чаще: открыть карточку по артикулу, записать цену и наличие. Каждая карточка самодостаточна, поэтому смена адреса между ними ничего не ломает.

Съём позиций по региону устроен иначе. Сначала сайт запоминает выбранный адрес доставки, потом отдаёт выдачу и следующие страницы. Пока цепочка не закончилась, адрес и cookie должны оставаться прежними.

Если карточки открываются в браузере, регион задают не только прокси. В документации Playwright об эмуляции описано, как задать браузеру язык, часовой пояс и геолокацию. Геолокацию там меняют сразу для всех страниц контекста, поэтому под каждый город удобно держать отдельный контекст со своим прокси.

Сколько адресов и трафика нужно

Объём мониторинга считают из трёх параметров задачи: сколько карточек, в скольких городах и сколько раз в сутки вы их проверяете. Число адресов зависит от городов и параллельных потоков, а трафик зависит от способа загрузки страниц.

Условный пример расчёта

Условный пример: компания следит за 400 карточками конкурентов в 6 городах и проверяет их 3 раза в сутки. Получается 400 × 6 × 3 = 7 200 загрузок карточек в сутки и 216 000 за 30 дней.

По адресам минимум такой: хотя бы один адрес или одна sticky-сессия на город, то есть 6. Если в каждом городе работают 2 параллельных потока, одновременно нужно 12 сессий.

Трафик важен, если тариф считается за гигабайты. По данным HTTP Archive Web Almanac 2024, медианная внутренняя страница на мобильных загружает 17 КБ HTML, а мобильная страница целиком весит 2 311 КБ. У карточек маркетплейса вес будет своим, поэтому медианы годятся только для порядка величин:

  • только HTML: 7 200 × 17 КБ = 122 400 КБ, это 122,4 МБ в сутки и 3,67 ГБ за 30 дней;
  • браузер со всеми файлами: 7 200 × 2 311 КБ = 16 639 200 КБ, это 16,64 ГБ в сутки и 499,2 ГБ за 30 дней;
  • разница между способами больше чем в 135 раз, поэтому способ загрузки решает больше, чем число городов.

Если цену и наличие можно взять из HTML, на карточку уходят килобайты, и оплату по факту трафика (pay-as-you-go) есть смысл сравнить с оплатой за IP. Если карточку нужно открывать в браузере, измерьте трафик на одну карточку на тесте и только потом сравнивайте модели оплаты за IP и за трафик.

Как держать темп запросов к площадке

Темп проверок задаёт ваш скрипт, а не прокси. Больше адресов не отменяет лимитов площадки, поэтому мониторинг замедляется по сигналу сайта, а не меняет адрес.

Такой сигнал описан в справке MDN о коде 429: клиент отправил слишком много запросов за отрезок времени. Если сервер добавил к ответу заголовок Retry-After, скрипт выдерживает указанную паузу.

До запуска откройте robots.txt площадки и её пользовательское соглашение. В RFC 9309 сказано, что правила robots.txt не являются формой авторизации доступа, поэтому одного файла мало. Таймауты, повторы и общий темп сбора разобраны в статье о прокси для парсинга, а состав и объём собираемых данных обсудите с юристом компании.

Как проверить выбор на тесте

Тест показывает то, чего не скажут ни сайт сервиса, ни рейтинг: совпадает ли то, что видит ваш скрипт, с тем, что видит покупатель в нужном городе. Проводите его на тех же карточках, городах и с тем же темпом, что в работе.

Для каждого города сравните две вещи. Первая: цену, наличие и срок доставки в карточке через прокси. Вторая: те же поля в обычном браузере, где город выбран вручную в интерфейсе площадки.

За тест запишите четыре числа:

  • долю карточек, где цена и наличие совпали с ручной проверкой;
  • сколько раз пришёл ответ 429 и что было в Retry-After;
  • сколько цепочек проверки выдачи дошли до конца без сброса города;
  • трафик на одну карточку, если тариф считается за гигабайты.

Если серверные адреса дают совпадение с ручной проверкой, переходить на резидентские незачем. Пробную закупку и условия до оплаты удобно сверить по статье о выборе прокси для компании.

Вопросы и ответы

Зачем нужны прокси для мониторинга цен на маркетплейсах?
Срок доставки, наличие на складе и место в выдаче связаны с регионом покупателя: Wildberries в справке для продавцов связывает среднее время доставки по регионам с позициями в поиске. Чтобы увидеть цены и наличие конкурентов так, как их видят покупатели в разных городах, нужен адрес в каждом из этих городов. Данные своего магазина при этом удобнее брать из API площадки.
Какие прокси нужны для Wildberries?
Для своих цен, остатков и аналитики прокси не нужны: Wildberries даёт API для продавцов с доступом по токену. Для открытых карточек конкурентов в одном городе тест можно начать с серверных IPv4, для нескольких городов смотрят резидентские адреса с выбором города. Проверять выдачу по региону удобнее в sticky-сессии.
Подходят ли те же прокси для Ozon?
Подход к выбору не зависит от площадки: данные своего магазина берут из инструментов для продавцов, а для открытых карточек выбирают тип адресов, город и режим сессии. Как именно площадка определяет регион покупателя, проверьте на тесте: по адресу доставки, по cookie или по адресу подключения.
Сколько прокси нужно для мониторинга цен конкурентов?
Минимум один адрес или одна sticky-сессия на каждый город, который вы проверяете. Если в городе работают несколько параллельных потоков, сессий нужно столько же. Число загрузок считают как карточки, умноженные на города и на проверки в сутки: 400 карточек в 6 городах трижды в сутки дают 7 200 загрузок.
Что выбрать для маркетплейсов: оплату за IP или за трафик?
Если цену и наличие можно взять из HTML, по медианам Web Almanac 2024 это 17 КБ на страницу, и оплату за гигабайты есть смысл сравнить с оплатой за IP. При загрузке карточек в браузере со всеми файлами объём по тем же медианам растёт больше чем в сотню раз. Поэтому сначала измерьте трафик на одну карточку на тесте.
